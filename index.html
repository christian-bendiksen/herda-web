Every change can be undone.

Herda keeps the system in versions. Installing or updating software applies right away and records a new system version, and earlier versions stay until you remove them. Your desktop settings keep a history of their own.

Two separate historiesRestoring a software version leaves your desktop settings as they are.
A way back after every releaseIf a new release doesn’t start correctly, Herda returns to the system that did.

Desktop configuration

From configuration to desktop

Smia is the source. Malm reviews and deploys it, smia-session activates it, and the Herda shell draws what you see.

Gnist changes themes at runtime. It reads one palette, renders theme files for each application and publishes the result under a stable current path.

Themes

One palette, everywhere you look.

A theme sets the colours for the whole system at once: the desktop shell, your applications, the terminal and the editor, icons and wallpapers. Gnist reads one palette, renders a theme file for each application and switches them while you work.

Updates when you ask for them.

Herda checks nothing until you ask. Package updates apply right away. A new release is downloaded, verified and built next to the system you are using, and takes over when you restart.

{{u.title}}{{u.desc}}
A new release takes effect after a restartPackage updates don’t wait for one.
{{p.l}}

If the new release doesn’t start correctly, Herda returns to your current system automatically.
